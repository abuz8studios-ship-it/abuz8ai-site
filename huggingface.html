⚡ Quickstart — from zero to a local model

  1. Pick your runner

    Ollama is the fastest path (one installer, one command). llama.cpp gives maximum control. LM Studio is the point-and-click option. Comparison table below.

  2. Find a GGUF on Hugging Face

    On huggingface.co/models, filter by the GGUF library tag, or search a model name plus "GGUF". Community quantizers publish ready-to-run files for most popular open models.

  3. Match the quant to your VRAM

    Use the quantization and VRAM tables below. Default pick: the Q4_K_M file that fits your GPU with a gigabyte or two to spare.

  4. Run it

    One command — see the code block underneath these steps. First run downloads or loads the model; after that it's instant and fully offline.

  5. Connect your apps

    All three runners expose an OpenAI-compatible local endpoint (Ollama: localhost:11434/v1 · llama-server: localhost:8080/v1 · LM Studio: localhost:1234/v1), so any tool that speaks the OpenAI API can point at your own machine instead.

# Ollama — easiest (after installing from ollama.com)
ollama run <model-name>

# llama.cpp — OpenAI-compatible local server
llama-server -m ./your-model-Q4_K_M.gguf -c 4096 --n-gpu-layers 99

📦 What GGUF actually is

GGUF is the single-file model format used by llama.cpp and everything built on top of it. One .gguf file bundles the weights, tokenizer and metadata; it supports quantized weights and is memory-mapped, so models load fast and don't need unpacking. When you see "GGUF" on a Hugging Face repo, it means: ready to run locally with the tools on this page.

🎚 Quantization levels — what the letters mean

Quantization stores weights in fewer bits, shrinking the file and the VRAM needed, at some cost in quality. Sizes below are approximate for an 8-billion-parameter model and vary by architecture.

🧮 How much VRAM do you need?

Rule of thumb: GGUF file size + 1–2 GB for the context cache and overhead. Longer context windows eat more VRAM. llama.cpp-family runners can split layers between GPU and CPU RAM (--n-gpu-layers) — slower, but it lets a big model run on a small card.

GPU VRAMComfortable fit (rule of thumb)
4 GB1–3B models at Q4
6–8 GB7–8B at Q4_K_M
12 GB8B at Q8, or 13–14B at Q4
16 GB14B at Q6, or ~20B class quantized
24 GB~30B class at Q4–Q5
32 GB~30B at Q6–Q8, or 70B at low quant with partial CPU offload
These are starting points, not laws — actual fit depends on context length, architecture and your OS's own VRAM use. Start one size smaller than you think, then move up.

⚖️ License first — always

"Open weights" is not one thing. The model card and LICENSE file on the model's own Hugging Face page are the source of truth — licenses vary by model and by version, so read the actual file before you build on anything.

📊 Benchmark caution

Leaderboard numbers are a starting point, not a verdict. Public benchmark scores can be inflated by training-data contamination, popular benchmarks saturate over time, and a two-point difference on a leaderboard rarely survives quantization and real workloads. The only benchmark that matters is your prompts on your hardware.
  • Define the job — chat, coding, summarization, vision, function-calling? Model families specialize.
  • Shortlist by size — only consider models whose GGUF actually fits your VRAM (see the Run Locally tab).
  • Check the license — table above; eliminate anything incompatible with your use.
  • Check GGUF availability — no GGUF usually means no easy local run.
  • Run your own 10-prompt eval — the same 10 real tasks against each finalist, judged by you.

Where do the numbers on this page come from?

What is GGUF?
The single-file model format used by llama.cpp and the tools built on it (Ollama, LM Studio and others). One .gguf file contains the weights, tokenizer and metadata, supports quantized weights, and is memory-mapped for fast loading.
Which quantization level should I download?
Q4_K_M is the widely used default balance of size and quality. Pick Q5_K_M or Q6_K if you have VRAM headroom, and treat Q2/Q3 quants as a last resort — the quality loss becomes noticeable, especially on smaller models. Full table in the Run Locally tab.
How much VRAM do I need to run a model locally?
Rule of thumb: the GGUF file size plus roughly 1–2 GB for the context cache and overhead. An 8B model at Q4_K_M (~5 GB) fits comfortably on an 8 GB GPU. llama.cpp-family runners can also split layers between GPU and CPU RAM, trading speed for capacity.
Can I use a Hugging Face model commercially?
It depends entirely on the model's license. Apache-2.0 and MIT are permissive; many popular open-weights models ship custom licenses with conditions; some are research-only. The model card and LICENSE file on the model's own page are the source of truth — always read them.
Do I need a Hugging Face account to download models?
For most public models, no — the files download directly. Some models are gated: you need a free account and must accept the author's terms on the model page before downloading.
